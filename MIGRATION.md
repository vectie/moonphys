# Extraction from MoonMoon

This is the local, unpublished module `vectie/moonphys@0.1.0`. Its implementation
was extracted on 2026-10-23 from `vectie/moonmoon@0.1.0` at repository HEAD
`38a9791b260516e67814d9e4c2aba52875880d02`; the original physics path's last commit
was `ba21f3985baeeb02a97bb03f0ad2f086ee27ef24`. MoonMoon's pre-existing dirty change
to `ui/rabbita-moon/moon.mod` was preserved.

## Ownership and source mapping

| Original MoonMoon path | Canonical destination | Treatment |
| --- | --- | --- |
| `src/moonphys/vector.mbt` | `vectie/moonnum/geometry/vector.mbt` | `Vec3`, its constructor, fields, JSON traits, and methods retain their implementation. |
| `src/moonphys/transform.mbt` | `vectie/moonnum/geometry/transform.mbt` | `Basis3`, `Transform3`, their fields, JSON traits, constructors, and methods retain their implementation. The shared `normalized_axis` helper becomes public so physics can call its owner. |
| Other production `src/moonphys/*.mbt` | This module's root, with the same filenames | Physical algorithms and records moved without semantic changes. `geometry.mbt` re-exports the shared geometry API and privately forwards the shared normalization helper. |
| `src/moonphys/moonphys_test.mbt` | `moonphys_test.mbt` | All 98 original test cases retained. |
| `src/moonphys/review/model_metadata.mbt` | `review/model_metadata.mbt` | The complete metadata inventory and readiness API retained. |
| `src/moonphys/review/model_metadata_test.mbt` | `review/model_metadata_test.mbt` | All 4 original test cases retained. |
| Both original `moon.pkg` files | Snapshots; replacement manifests define new dependencies | Root depends on core math/JSON and `moonnum/geometry`; review depends on core JSON. |
| Both original `pkg.generated.mbti` files | Snapshots; new interfaces generated by `moon info` | Public physical type ownership changes to MoonPhys, and geometric ownership changes to MoonNum. |

The production files include angular dynamics, articulated kinematics, collision
shapes and manifolds, contacts, dynamic stability, environments, heightfields,
joint control, kinematics, motion-frame reviews, rigid-body and wrench integration,
distance and hinge constraints, heightfield worlds and their target/support/replay
assessments, traces, support calculations, and their private utilities. The
original lunar convenience presets remain available and require no MoonMoon data.

The full per-file mapping is
[`docs/provenance/moonmoon-moonphys-20261023/manifest.json`](docs/provenance/moonmoon-moonphys-20261023/manifest.json).
It records the original path, destination, byte count, and original SHA-256 for
all **37 files**, including **33 `.mbt` files**. Each original file is preserved
byte-for-byte beside the manifest with a `.source` suffix. Those snapshots have
no `moon.pkg` and are not compiled. They are historical evidence, not a second
implementation to maintain. The original Apache-2.0 license is copied to `LICENSE`.

The current formatter normalizes `Int` to its `Int32` alias, defaulted parameter
labels from `?` to `~`, trailing commas, and line wrapping. These syntax-only edits
are allowed by the provenance audit. String/character literal contents remain
exact. The only additional visibility edit is the geometry normalization helper;
no equations, thresholds, enum cases, record fields, or JSON field names changed.

## Compatibility and dependency boundary

MoonMoon's `src/moonphys/compatibility.mbt` and
`src/moonphys/review/compatibility.mbt` are generated `pub using` facades. They
forward all **233 original root declarations** and **4 review declarations**.
Methods resolve through the canonical public type owner rather than copied
definitions. Consumers can mix a legacy `@moonphys.Vec3`, a new
`@physics.Vec3`, and `@geometry.Vec3` without conversion. Physical records likewise
have one canonical identity. Generated interfaces document these owners.

MoonBit's type re-export does not expose a constructor under the facade's short
package-qualified spelling. For the one original enum, use
`@legacy.CollisionShapeKind::SphereShape` (likewise `CapsuleShape` and `BoxShape`),
or a constructor inferred from a known `CollisionShapeKind`, instead of
`@legacy.SphereShape`. The enum type, cases, and encoding are unchanged. Existing
MoonMoon consumers needed no source changes for this qualification issue. Three
new compatibility test cases typecheck geometry/method lookup, physics records
and enum matching, and review-record identity; execution remains deferred.

The dependency graph is:

```text
MoonMoon / MoonRobo consumers
             |
             v
      vectie/moonphys --------> vectie/moonnum/geometry
        root + review             geometry owner
```

MoonPhys imports no MoonMoon or MoonRobo package, terrain/catalog/mission data,
robot SDK, UI, Python, MuJoCo, or training backend. The physical approximations and
review calculations retain their original scope; extraction does not introduce a
new external simulator or make a numerical parity claim about one.

Local workspace membership is explicit:

| Workspace | Members |
| --- | --- |
| MoonPhys `moon.work` | `.`, `../moonnum` |
| MoonMoon `moon.work` | `.`, `../moonphys`, `../moonnum` |

`moon.mod` declares `vectie/moonnum@0.1.0`; MoonMoon declares both new modules at
`0.1.0`. Workspaces supply these unpublished modules locally. No package was
published and no remote dependency was substituted for the local implementations.

## Reproduction and verification

The MoonBit automation is `../moonmoon/scripts/extract_moonphys.mbtx`. Its
`extract` mode snapshots every original file before replacing old implementations
with facades, and refuses to overwrite an existing manifest. Its
`refresh-facades` mode regenerates only the forwarding declarations from the
archived interfaces. Its `verify` mode is read-only:

```sh
# Run from the MoonMoon repository root, with actual absolute checkout paths.
moon run --target native scripts/extract_moonphys.mbtx -- verify /ABSOLUTE/moonmoon /ABSOLUTE/moonphys
```

The completed audit verified **37 original SHA-256 entries**, all **33 relocated
source files** after the documented formatter normalization, **102 preserved
original test cases**, and **149 unchanged public function/method signatures**
across the physical, shared geometry, and review owners.

Completed compilation checks (no test execution):

- MoonPhys's complete workspace: `moon check --target all`.
- MoonMoon's complete workspace: `moon check --target all`.
- Explicit affected-package check for both compatibility packages,
  `src/suite_adapter_preview`, and `cmd/suite_preview`, across all backends.
- MoonMoon's separate Rabbita UI workspace: `moon check main --target js`.
- Native typechecking of the extraction/verification `.mbtx` tool.
- Scoped `moon info` and `moon fmt`, with regenerated public interfaces reviewed.

The toolchain's `all` selection checks Wasm, Wasm GC, JavaScript, and native here.
It typechecks the test sources, including original tests and the new compatibility
contracts. Existing deprecation/unused-import warnings remain. No test, simulation,
training, hardware operation, or external physics calculation was run. Numerical
behavior is supported by the unchanged algorithms and compile-time API audit;
runtime regression results are intentionally pending until the user makes the
machine available.
